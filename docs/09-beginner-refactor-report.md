# 入门层改造报告：23 种模式怎么讲才不是背定义

> 采集时间：2026-10-27。本文所有数字都来自实际命令输出，验证脚本在 `_verify/` 下，可重跑。
> 改造目标不是增加理论，而是让第一次接触设计模式的人能回答四个问题：
> **原来哪里疼？每个新对象为什么存在？对象之间怎么协作？我这个场景到底该不该用？**

## 1. 改造范围与边界

| 做了什么 | 没做什么 |
|---|---|
| 23 种模式各新增一份 `BEGINNER.md` | 没有删改任何既有深度 `README.md` 的正文 |
| 23 种模式各新增一个 `beginner/BeginnerDemo.java` | 没有把工程版 `Client.java` 改成教学版 |
| 深度 `README.md` 顶部加一行入门回链 | 没有引入框架、构建工具或第三方依赖 |
| 根 README 增加两层入口与 23 篇索引 | 没有把「可选扩展」写成模式必备能力 |
| 统一八段式模板沉淀为 `docs/08` | 没有编造业务数据；输出均来自实跑 |

分层是这次改造的核心约束：

| 层级 | 文件 | 读者 | 回答的问题 |
|---|---|---|---|
| 第一层：入门 | `BEGINNER.md` + `beginner/BeginnerDemo.java` | 学过 Java 语法，没系统学过模式 | 为什么用、什么时候不用 |
| 第二层：深度 | `README.md` + 工程版 `Client.java` | 已理解动机，要做实现或面试 | 角色、协作、扩展、异常边界 |

初学者不需要先读 5000 行深度文档，也不会因为只读入门层就以为模式等于「抽接口加多态」。

## 3. 八段式怎么落地

每份 `BEGINNER.md` 固定八段，顺序本身就是教学法：先让问题发生，再给解法。

1. **一句话说人话 + 具体场景**：不先给定义，先说「它把什么麻烦变成了什么方便」。
2. **不使用的完整可运行代码**：短、能跑、只暴露一个核心矛盾。
3. **结合代码解释为什么疼**：谁依赖谁、改一处要动几处、为什么加 `if-else` 不够。
4. **逐步推导设计**：每加一个抽象都回答「为什么加、解决什么、不加会怎样、和相邻类有什么区别」。
5. **具体数据走一遍执行顺序**：用确定的输入和真实输出，配 ASCII 依赖图。
6. **改造前后对比**：新增一个需求分别要改哪里，成本差多少。
7. **适用边界与易混模式**：明确写出「什么时候不该用」。
8. **2-3 道递进练习**：至少一道场景判断、一道解释设计原因，附答案与推导。

### 3.1 23 个模式不是同一个故事

入门材料最容易犯的错，是把所有模式都讲成「if-else 太多，所以抽接口」。实际写作时按痛点分组，每组讲不同的矛盾：

| 痛点类型 | 模式 | 不用时的具体表现 |
|---|---|---|
| 唯一性与共享 | 单例、享元 | 多份状态不一致；十万字符各存一份样式 |
| 创建散落 | 工厂方法、抽象工厂、建造者、原型 | 新增类型改多个调用点；构造器参数爆炸；拷贝漏字段 |
| 接口不兼容 | 适配器 | 调用方被迫理解厂商的单位与命名 |
| 维度相乘 | 桥接、装饰器 | 消息类型 × 渠道、咖啡 × 加料，继承层级爆炸 |
| 结构递归 | 组合 | 客户端 `instanceof` 递归，加节点类型就改遍历 |
| 入口编排 | 外观 | 每个调用方重复排子系统顺序、漏步骤 |
| 访问控制 | 代理 | 每个调用方重复鉴权、重复加载 |
| 流程重复 | 模板方法、责任链 | 五步流程各写一遍；金额规则写死，加一级改方法 |
| 请求与规则对象化 | 命令、解释器 | 加任务改调度器、失败整批中断；换规则改代码 |
| 遍历与操作外置 | 迭代器、访问者 | 暴露内部存储；加一种导出格式改所有元素类 |
| 依赖成网 | 中介者、观察者 | 同事互相持有，N×N 依赖；下单服务直接依赖所有通知方 |
| 状态与算法 | 状态、策略 | 每个方法都写状态 `if`；加折扣改结算方法 |
| 状态快照 | 备忘录 | 客户端自己管快照，字段一多就漏 |

完整对照表（场景、痛点、关键抽象、最易混淆模式）在 [08-beginner-teaching-template.md](08-beginner-teaching-template.md) §4。

### 3.2 明确区分「模式给的」和「自己要加的」

这是本次改造反复强调的一条边界。典型例子：

| 模式 | 模式本身提供 | 需要额外机制 |
|---|---|---|
| 命令 | 请求对象、统一 `execute`、调用者与执行者解耦 | 队列、异步、持久化、重试、事务、撤销 |
| 观察者 | 一对多注册与回调 | 失败隔离、异步投递、顺序保证、去重 |
| 备忘录 | 不透明快照、原发器自恢复 | 历史容量限制、磁盘持久化、合并快照 |
| 状态 | 状态对象委托、非法流转拒绝 | 状态机可视化、持久化、并发控制 |
| 策略 | 可替换算法、运行时切换 | 策略叠加、优先级、组合规则 |
| 模板方法 | `final` 骨架、步骤顺序固定 | 需要组合而非继承时，应改用策略 |

入门 Demo 里如果演示了队列、失败隔离之类的能力，文档会明确写「这是发布策略/调度层加的，不是观察者/命令模式自动送的」。

## 4. 代码约定

23 个入门 Demo 遵守同一组约定，保证「编译一次就能对照」：

- 单文件，类名统一为 `BeginnerDemo`，放在各模式的 `beginner/` 子包；
- 只用 `class` / `interface` / `List` / `Map` 等基础语法，不用 record、sealed、注解、框架；
- `main` 先跑 `before()`（改造前），再跑 `after()`（改造后）；
- 输出确定：无时间戳、无随机数、无线程调度、无哈希地址；
- 业务失败用返回值或 JDK 异常表示，不引入自定义异常体系，并在文档中说明这是简化；
- 输出中包含「问题清单 / 代价」，让代码自己讲边界。

## 6. 已知问题

| 问题 | 影响 | 现状 |
|---|---|---|
| `build.bat` 运行循环把绝对路径当类名 | 编译正常但 25 个入口全部报「找不到主类」 | **已修复并实测**：改用 `%~dp0` 拼绝对路径，并在 `for` 循环内直接运行。`cmd /c build.bat` 退出码 0，25 个入口全部启动，0 个「找不到主类」。注意：`.bat` 必须保存为 GBK（与 cmd 默认代码页一致），存成 UTF-8 会让中文后的 `!` 被吞掉 |

## 7. 怎么开始读

1. 打开任意模式的 `BEGINNER.md`，先读第 1、2 段，把「不用的代码」跑一遍；
2. 合上文档，自己回答「原来哪里疼、每个新类解决了什么、什么时候不该用」；
3. 再读同目录的 `README.md` 和工程版 `Client.java`，看真实项目怎么处理异常、扩展和边界；
4. 按 [01-learning-path.md](01-learning-path.md) 的顺序推进，不要按字母顺序刷。
