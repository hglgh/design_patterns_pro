# 综合练习

> 五个真实业务任务。每个都按「**先思考，后看答案**」组织：前一半只给需求和问题，参考答案折叠在后一半。
>
> 目标不是"再做五个 Demo"，而是练一件事：**面对一段还没写出来的需求，能不能自己推出结构和职责。**

---

## 为什么要有这一章

前 23 个模式是**分门别类**学的：一个模式一个 Demo，边界清楚。

但真实工作不是这样。真实工作是：

> 运营说"优惠券要能叠加，但不能叠太多"。
> 产品说"订单状态要能配"。
> 老板说"这个功能下周上线"。

没有人会告诉你"这里该用责任链"。**你必须自己从需求里看出变化点，然后决定：用一个模式、用几个模式，还是干脆不用。**

这一章就是练这个。

## 建议顺序

```
01 优惠计算   →   02 状态流转   →   05 请求管线   →   04 文件导出   →   03 通知
   ↑                                                              ↑
   五个变化维度                                   最简单，适合先热身
```

**如果你想先热身**：从 [03 消息通知](03-notification.md) 开始。它只有一个真正需要判断的点（广播 vs 链），40 分钟能做完。

**如果你想直接练综合**：从 [01 优惠计算](01-order-discount.md) 开始。它是唯一一个"必须同时用三个机制"的练习。

**02 和 05 是同一条线上的两端**：02 管"一个对象的状态怎么变"，05 管"一个请求怎么穿过多个对象"。做完 02 再做 05，你会发现"托管状态"和"串联处理"是两种完全不同的组织方式。

**04 单独看**：它不涉及多个对象协作，只涉及"变化维度怎么拆"。适合在读完模板方法之后立刻做。

## 每个练习的结构

所有练习文档都是同一套骨架：

## 怎么用这些练习

### 不要这样用

- ❌ 直接翻到第 6 节，看答案，觉得"哦我懂了"。
- ❌ 把参考实现复制到项目里当模板。
- ❌ 只看 UML，不写代码。

### 建议这样用

1. **先读 1~3 节**，在纸上把需求画成一个"变化清单"（哪些会变、多快变、谁在提）。
2. **做完 4 节的三道题**，哪怕写得乱七八糟。**手写比脑补有效 10 倍。**
3. **用 5 节的自检表打分**。打分低就先别往下看，回看对应模式文档。
4. **再看第 6~9 节**，重点看"我漏了哪些变化点"。
5. **最后跑一遍参考实现**，对着输出看自己的设计会得到什么结果。
6. **合上文档，从零重写一遍**。这一遍不看答案。

### 一道题的"做完"标准

不是"想出来了"，而是能回答下面三个问题：

- 我的设计里，**加一种新需求要改几个文件**？
- 如果**不用模式**，会坏在哪里？**坏在什么时候暴露**（编译期？运行时？半年后？）
- 我的设计里，**哪一部分是我刻意没抽象的**？为什么？不抽象的那部分靠什么保证正确（测试？类型？约定？）

第三个问题最重要 —— **成熟的标志不是"我都抽象了"，而是"我知道哪些不该抽象"。**

## 五个练习合起来练的是

```
练习 01  怎么把一个方法里的 if-else 拆成三个正交的变化维度
练习 02  怎么在「对象」和「数据」之间做取舍，而不是默认选对象
练习 03  怎么看穿"一对多"背后的真实拓扑
练习 04  怎么让两个维度独立扩展，避免笛卡尔积
练习 05  怎么识别「一个机制解决不了的事」，并给它们找到别的归宿

   ↓ 合起来

面对一段需求，先数变化维度 → 再判断每个维度的机制 → 最后检查机制之间有没有残余问题
```

这套流程的完整方法在 [选择指南](../pattern-selection-guide.md)。

## 参考实现的运行方式

五个参考实现都是**单文件源模式**，不需要先编译：

```bash
java docs/practice/solutions/OrderDiscountSolution.java
java docs/practice/solutions/OrderStateSolution.java
java docs/practice/solutions/NotificationSolution.java
java docs/practice/solutions/ReportExportSolution.java
java docs/practice/solutions/OrderApiSolution.java
```

Windows PowerShell 下如果中文输出乱码，加编码参数（**注意引号不能省**）：

```powershell
java "-Dstdout.encoding=UTF-8" docs\practice\solutions\OrderDiscountSolution.java
```

> **为什么这五个文件不放在 `src/` 下**：它们是**教学用**的，每个文件里都刻意塞了对照实现和反例，方法论上不属于某种模式的正式实现。放在 `docs/practice/solutions/` 是为了让读者知道"这是参考答案，不是工程代码"。
>
> 想看工程版怎么做，去 `src/com/patterns/combined/`。
